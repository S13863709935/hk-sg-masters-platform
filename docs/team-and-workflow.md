## 后续开发批次（2026-10-29 用户确认）

用户后续说“继续”时，按以下顺序推进完整批次，不再默认每次只检查一门课程：

1. 先收敛匹配实用性：让用户看清已符合的公开门槛、明确缺口及仍待确认的条件；未知条件不得自动视为满足，不能据此生成录取概率或保底承诺。
2. 优先整理现有数据，按学校批量检查来源、课程身份、入学要求及日期／费用的适用范围，并明确未解决项。
3. 在匹配与现有数据质量稳定后，再按学校扩展覆盖；根据实际工作量确定批次边界，不要求每门课程都由用户再次发送“继续”。
4. 每批完成后汇报实际改动、验证结果、剩余问题及下一批重点，并给出是否建议推送 GitHub 的理由。推送仍按 `publication-policy.md` 执行，“继续”本身不触发推送。

这一顺序用于后续开发，不代表已有数据已全部核实，也不代表团队已完成独立复核。
