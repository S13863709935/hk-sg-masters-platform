# 本地运行与维护

当前版本：0.1.0，2026-10-06。

## 开始使用

Windows 双击仓库中的 `start-local.cmd`。启动窗口显示网址后，打开 `http://127.0.0.1:3102`。保持启动窗口运行，关闭窗口或按 Ctrl+C 会停止服务。

运行环境需要 Node.js 24 或以上。启动脚本优先使用已安装的 Node；没有合适版本时，会检查当前用户已有的 Codex 内置运行环境。其他组员没有该环境时，应安装 Node.js。网站运行无需安装额外软件包。

命令行也可以在项目目录运行：

```text
node server/index.mjs
```

或使用 `npm start`。端口已占用时，在 PowerShell 中先设置 `$env:PORT = '3103'`，再启动，然后打开相应端口的网址。

## 已实现的流程

- 全英文界面、关键词搜索、地区／学校／内容标签／模式／核验状态筛选和分页。页面不读取旧语言偏好，也不提供语言切换。
- 项目详情、不同学习模式的费用及适用周期、官方来源。
- 自报背景输入、单次考试和语言单项检查、GPA 原始量表检查、逐条件理由。
- 浏览器候选清单、最多四个项目的并排比较及候选 JSON 导出。
- 数据状态工作台、公共课程 JSON 导出、本地批次导入和变更日志。
- 具备“冲刺／匹配／相对稳妥”规则实现，但现有数据没有完成条件核验与独立复核，因此真实项目暂不强行分档。

这些功能不构成已完成全部课程数据核验或完成公开部署。

## 数据在哪里

`data/catalogue.json` 是从原始工作簿提取的 175 条种子，保留了旧稿的状态和备注。旧稿内容标签可能不准确，不作为本科专业门槛依据。旧要求备注不参与自动判断。

`data/checked-programmes.json` 保存首批 20 个直接申请项目和 1 个转入限定项目的部分官方页面数据。项目页已查 21，独立复核 0、完整要求 0。`catalogue-expansion.json` 另有 186 条未核验目录线索；合计 361 条、默认浏览 360 条。原始 175 条及稳定 ID 保持不变。

SQLite 数据库首次启动时创建在 `data/local/platform.sqlite`，不上传 GitHub。数据库含学校、课程、学习选项、条件、元数据及变更日志，不含学生档案表。重启不会清除导入的课程修改。

## 核验和导入

先从数据工作台导出 JSON，复制待更新的完整项目对象到新的批次文件。顶层使用 `schemaVersion: 1` 和 `programmes` 数组，字段格式参考 `data/checked-programmes.json`。每条结构化要求必须带大学官方 HTTPS 来源。

```text
node scripts/import-data.mjs path/to/checked-batch.json
```

批次会整体校验并在一个数据库事务内导入。任何一条不合法时全部回滚。修改记录包含实际时间、原因及修改前后内容。`peer_reviewed` 状态必须记录不同的采集人与复核人，不能冒填团队姓名或完成状态。

修改源文件后重启服务。`catalogue.json` 只用于初次建库；`catalogue-expansion.json` 只添加新 ID，不覆盖既有用户更新；`checked-programmes.json` 内容变化会在启动时作为结构化批次应用。日常采集更新使用批次导入，不编辑原始工作簿或删除数据库。

## 可选目录研究工具

`collect-directory.mjs` 对指定公开目录进行有超时和体积限制的读取，最多两个请求并行；拒绝或读不到的页面保留为未知，不绕过访问限制。HTML 解析使用用户显式提供的 Python 及已安装的 lxml，仅用于研究，不是网站运行依赖。候选输出不自动变成已核验招生数据。

`build-directory-inventory.mjs` 使用 2026-10-08 已保存的目录快照和本轮范围规则生成排除清单及未核验扩展层，保留已有 ID。目录结构／学校范围变化时需重新审查规则，不能把该脚本当成无需人工检查的长期爬虫。重复运行只更新同一批研究派生文件，不产生新周次或伪造贡献。

## 网页导入权限

默认关闭。需要使用时，在启动前将 `ADMIN_TOKEN` 设置为至少 24 个字符的随机令牌，再通过数据工作台输入该令牌和 JSON 文件。网页不保存令牌，鉴权成功且来源校验通过才会写入数据库。令牌不得提交到仓库。

`.env.example` 只是字段示例，程序不会自动读取它；通过启动服务的终端设置环境变量。未设置令牌时本地命令行导入仍可使用。

## 判断规则与局限

必需条件有明确失败时显示缺口，同时保留其他未知条件。没有失败但有未知必需条件时显示需确认。只有全部已记录必需条件可判断时，才显示已核查条件达标，不表示学校确认最终资格。

GPA 仅比较相同原始量表，不线性换算。荣誉等级不从 GPA 推断。明确的相关专业、英语豁免、院校认可及同等资格仍需要学校判断。托福版本与 2026-01-21 前后的考试日期分别检查。

分档只对条件完整、路径明确且有独立复核的记录启用。相对稳妥表示自报成绩在相同尺度上高于已记录最低值并且背景相关，不设额外录取线，也不估算录取概率。未知偏好条件同样会阻止分档。

## 隐私及运行边界

服务只监听 `127.0.0.1`，不是公开部署方案。外部 Origin 的写请求被拒绝，后台导入需要令牌，静态文件白名单不暴露服务器代码、原始数据文件或数据库。

背景只临时传给本地服务做判断，不入库、不写请求日志。只有用户勾选保存时，背景才存入当前浏览器。候选清单保存在浏览器。导出候选只包含项目和来源，不包含背景。页面有清除背景功能。

公开部署之前仍需另行评估 HTTPS、鉴权、流量限制、备份、隐私规则和最新课程数据，不能直接向公网绑定当前本地预览。

## 测试

```text
node --test tests/*.test.mjs
node scripts/check-data.mjs
```

测试中的 GPA、偏好条件和“完整核验”项目是合成测试对象，不会导入实际目录。数据库持久化测试只创建和清理自己的临时测试数据库。

英文界面检查覆盖启动文案、导航、表单、日期格式、站内文件选择提示、数据说明、条件理由和校验错误。原始工作簿及内部采集备注保留原文，不改变来源证据。
