# Staged publication policy

Effective from the user's direction on 13 October 2026.

Local development may advance beyond the project timetable. Remote commits and pushes publish only the selected stage deliverables, not all local work.

- Start each checkpoint from the shared baseline or an approved earlier checkpoint.
- Select files and dependencies by the action plan. Do not push an ahead-of-plan branch wholesale.
- Keep real commit dates, actual source-check dates, unknowns and review limitations.
- Never fabricate weekly activity, participant feedback, contributions or independent review.
- Do not include private student data, CVs, signatures or local configuration.
- Push the checkpoint branch for review. Keep main unchanged until the agreed review/merge step.

This is a publication workflow, not an automatic schedule or an assertion that every planned task is complete.

## Delegated checkpoint timing — 20 October 2026

The user now delegates judging when to commit and push. During active development turns, assess plan fit, completed evidence, tests, privacy and dependency boundaries; publish a review-ready checkpoint without waiting for another reminder. This is not a background automation or permission to publish the advanced local branch wholesale.

Study Week is 19–25 October, not Week 6. A small progress checkpoint may be published before the period ends if its limits are explicit. Never mark pending user research, team acceptance or independent review complete. Keep `main` and historical checkpoint branches unchanged unless a separate review/merge step is authorised.
