# Windows解压交付修复（11月10日）

用户实际用资源管理器的“全部解压缩”打开演示包时，系统报告ZIP无效。此前包内文件校验、其他读取程序及临时启动通过，没有覆盖这一实际入口。该交付兼容性缺口属于本轮修复，不将旧验收结果当作资源管理器解压成功。

原归档由tar自动选择ZIP格式，包含./根条目、Unix目录属性及扩展字段。它能被Python ZIP读取并通过CRC检查，但不能据此保证Windows Shell兼容；很深的默认文件夹也会增加传统路径限制的风险。本修复不将某一项推测认定为唯一原因。

新打包工具只写标准ZIP32、DEFLATE与UTF-8文件名，使用预先计算的CRC和长度；不写./根、目录条目、Unix额外字段或流式长度描述。归档路径必须规范、唯一且不越界，超出ZIP32容量明确报错。仍采用原来的隐私白名单与源文件指纹，不引入第三方依赖，也不更改网站功能或大学资料。

相关4项检查通过：Windows自带解压命令实际恢复嵌套、Unicode、空文件及二进制内容；非规范／重复／越界条目拒绝；既有隐私筛选保留。新完整包另外从短路径解压，按LOCAL-DELIVERY.json核对全部源文件后再实际启动。交付旁的检查结果记录实际完成情况；旧包保留，不覆盖用户文件。

本轮仅本地提交与重新交付，不推送、不部署。W8及原日常数据库保持不变。建议直接使用本次新包或已解压文件夹；其他电脑仍需Node.js24或以上。
